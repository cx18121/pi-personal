# Delivery

Determine the requested action and target from the explicit instruction and current project context. Commit, push, pull request, merge, publication, deployment, and production mutation are distinct permissions.

Preserve unrelated work and prepare only the intended delivery unit. Use `commit-style` for commit or pull-request titles and `pr-description` for pull-request prose. Resolve known defects that matter to the requested stage, or report them plainly when delivering an explicitly incomplete artifact such as a draft.

Verify the state you will claim using its authoritative source. Keep changed, verified, committed, pushed, CI green, merged, deployed, and production-observed states distinct. Existing receipts establish what happened, not authority for a further action.

Hand back the result, the actual delivery state, and meaningful unresolved limits. Completion in one repository or environment says nothing about another.
