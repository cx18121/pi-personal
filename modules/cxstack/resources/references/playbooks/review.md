# Review

Use for explicit review requests or consequential artifact judgment. This route is read only. Fixing a finding requires a visible change route, followed by targeted verification of the fix and affected behavior.

1. **Establish the review contract.** Name the exact artifact, fixed point, originating intent, audience, confirmed decisions, project standards, changed files, evidence, and claims. Do not let the author's explanation replace primary sources.
2. **Run Simplify when earned.** Load the installed `simplify` skill from `~/.agents/skills/simplify/SKILL.md` when the artifact is consequential or the user requests a simplification pass. Identify complexity that can disappear without changing the intended result.
3. **Run Thermo when triggered.** Load `thermo-nuclear-code-quality-review` from `~/.agents/skills/thermo-nuclear-code-quality-review/SKILL.md` for most PR-sized production changes and whenever the change is structural, cross-cutting, abstraction-heavy, shared, or difficult to understand from callers. A skip stays visible with a reason.
4. **Disposition maintainability findings.** The parent verifies each finding as accepted, rejected, or unresolved against the review contract. When fixing is authorized, enter the appropriate change route for the accepted batch, verify the fixes, then continue to correctness review. Completed unaffected review work still counts.
5. **Run one Correctness Review when earned.** After no accepted maintainability fix remains, launch one fresh child using the Correctness Review contract only when a wrong result is costly, hidden, hard to undo, or materially affects production, persistent data, security, money, deployment, shared interfaces, or durable architecture. Fold spec alignment into correctness. Mechanical standards stay tool-enforced.
6. **Disposition correctness findings.** Verify every finding against current source and the review contract. An accepted fix leaves Review for the appropriate change route, then continues to targeted verification below. Report an unchanged unresolved claim rather than looping.
7. **Verify affected behavior.** The parent checks accepted fixes against their reproductions and affected callers or invariants, rerunning checks invalidated by the changes. Independent non-destructive checks may run during Correctness Review under its safety conditions. Another full independent review requires a named material risk that targeted verification cannot resolve. Changed code alone is not that reason. Unaffected checks and review conclusions still count.
8. **Reconcile the result.** Finish when the contracted outcome has evidence and no unresolved blocking finding remains. A fresh clean review is not a separate completion requirement. Report broken outcomes, missing proof, accepted decisions, residual risks, and actual delivery state. A clean verdict names the important surfaces checked and proof boundary.

A blocking finding needs a concrete broken outcome, violated invariant, material risk, or missing proof tied to the agreed outcome or a regression introduced by the change. Keep unrelated improvements and speculative hardening outside the repair batch and completion gate. A necessary material scope change returns to Investigation and Decision.
